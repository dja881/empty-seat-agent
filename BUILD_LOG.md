| Date | Tool | What AI did | Decision I made |
|---|---|---|---|
| 9 Oct | Claude Code | Read the challenge brief and the PRD, and raised gaps and contradictions before writing code: wave size vs customer count, a 4 pm walk-in conflict, who buys the slots in the 2 to 6 pm montage, floor prices stored per merchant instead of per service, webhooks not reaching localhost | Build straight from the PRD, no trimmed spec. Public GitHub repo as the code submission, deployed to Vercel from day one |
| 9 Oct | Claude Code | Wrote a deterministic seed generator: 60 customers across types (due, lapsed, regulars, VIPs, opted out, far away, recent), today's calendar designed to give 32 empty slots, 26.5 free chair-hours and 55.8% full, 90 days of history with walk-ins peaking at 4 pm, and about 52 synthetic merchants' hourly payments running 20% below normal today | Seed numbers must reproduce the PRD's demo day exactly. Hold the 5 pm block for walk-ins and release two 4 pm chairs for Riya and her sister |
| 9 Oct | Claude Code + in-app browser | Built the chair board as a standalone screen with Realtime updates, then checked every block state (booked, free, held, offered, released, paid) against live data | Chair board first, as the visual anchor for the video, before any other screen |
| 9 Oct | Claude Code + in-app browser | Took my mockups apart (a bundled HTML export of 10 screens), researched how Fresha, Square Appointments, Zenoti and Razorpay's own dashboard lay out a merchant's day, and rebuilt the UI: salon workspace with an account switcher, staff-column day calendar with service colours, dense tables instead of cards | Rejected the first build as "too AI-looking". Chose staff columns over chairs-as-rows because every salon tool works that way. Razorpay appears only where it would in real life (checkout, test mode, Agent Studio). WhatsApp replies must be live, not a static chat on the side |
| 9 Oct | Claude Code | Built the live loop: planner (walk-in forecast from same-weekday history scaled by area footfall; hold and release per hour), customer ranking, wave 1 as an approved WhatsApp template, the salon agent on Qwen returning JSON actions, and the pay page opening real Razorpay Checkout (HDFC-only block for the bank-funded price) | Live in-app phone rather than the real WhatsApp API, to cut setup risk with 4 days left. Prices, floors and times are enforced in code; the model only proposes |
| 9 Oct | Claude Code + Supabase | Wrote settle_offer() so the first confirmed payment wins inside one transaction: it carves the paid time out of the free block, cancels overlapping offers, books the customer, and a second payment is refunded | Floor checked on what the salon receives (₹330 + ₹50 HDFC clears a ₹350 floor) |
| 9 Oct | Claude Code | Simulator for demo mode only (wave 1 buyers, 1:30 pm footfall release of the held 5 pm hour, wave 2, walk-ins into held time, a call-me). Tuned so the demo day lands on the PRD's base case: 7 slots, ₹3,160, ₹150 HDFC-funded (₹200 from 11 Oct, once a brand offer was added) | Simulated customers only in demo mode; in live mode judges type as the customer and pay for real in test mode |
| 9 Oct | Claude Code | Daily report, settings, front desk, agent-to-agent negotiation (two Qwen agents with private limits, a real Razorpay order on a deal; removed from the demo on 12 Oct), landing page | Benchmark shows what similar salons fill on their own (18%) vs with the agent (30%), not a made-up gap |
| 9 Oct | Claude Code | Caught its own mistake: replies it had reported as "live" were the scripted fallback, because the model name in .env.local had been reverted and every model call returned 404. Fixed the model, re-ran every agent, and now tags each reply "model" or "script" | Keep the scripted switch as a recording safety net, but the default path must be the live model |
| 9 Oct | Claude Code | Rebuilt the dashboard as one guided page (morning plan, choose customers, live sales, day report) with a single Next button, a "Start my day" wake-up with the agent's voice, and typing as well as tapping for both owner and customer | After my first walkthrough: the screens were hard to follow and too cluttered. Show only the core journey, one focus per stage. The agent should wake when I press a button, not talk on its own |
| 9 Oct | Claude Code | Fixed what my walkthrough found: "₹200 is too much, do ₹150" skipped straight to sending; the phone opened too fast; UPI and the HDFC test card failed in Razorpay test mode while Netbanking worked | A plan change and an approval are separate steps. Netbanking is listed first in test mode, with a hint on the pay page |
| 10 Oct | Claude Code | Stopped wasted credits: the 1:30 pm alert is spoken only when it happens live, the negotiation runs only when asked, a voice on/off switch and a visible Restart demo button | Voice and model calls only when they add to the demo. I wanted to ideate before changing more, so no other changes that day |
| 10 Oct | Claude Code | Rebranded the demo salon to Strand & Co. from my logo and opening-screen files, turned agent-sold slots green, and labelled chairs by role (Senior stylist, Barber) instead of six stylist names. Set up a safety routine first: work on a branch, tag working versions, run a scripted demo-day test, merge only if it passes | I was worried changes would break what worked, so every change now goes through that routine. Green reads as "sold" better than amber. Roles are easier for a viewer than names |
| 11 Oct | Claude Code | Replaced the day report with my HTML design: extra revenue after what would have come in anyway and the agent's fee, a monthly discount budget, and what the agent learned for next week | The report should be about profitability and budget, not a list of bookings |
| 11 Oct | Claude Code | Renamed the agent to RAY with a male voice, and added a brand-funded offer (hair spa, any payment method) next to the bank-funded one (HDFC cards only). One rule in code decides which applies | RAY is the name of Razorpay's own agent. Bank offers alone don't show the partner model; a brand example was needed. Both partnerships are illustrative |
| 11 Oct | Claude Code, with a second reviewer's notes | Checked each review point against the code before changing anything. Real: three "start" prompts in a row, "32 chairs" for 32 slots, a customer and the receptionist both called Sneha, bookings moving to a new time with no explanation, a chair card saying "₹380 paid" when the customer paid ₹330. Not reproduced: one label the reviewer saw in an older version | I chose which points to fix and which to skip. The owner in the demo is me, not a made-up name |
| 11 Oct | Claude Code | Found and fixed a real bug from the review: if you skipped ahead before paying as the customer, a simulated buyer took her slot. Keep the bring-a-friend story, pay together |
| 11 Oct | Claude Code | One test run ended ₹60 short. | 11 Oct | Claude Code | Built a 10-step guided tour from my spec and mockups: outline on the target, dimmed page, auto-advance when the action is done, and a switch to turn it off | Judges need guiding through the journey; I need it off when recording.
