## Build log

| Date | Tool | What AI did | Decision I made |
|---|---|---|---|
| 9 Oct | Claude Code | Read the challenge brief and the PRD, and raised gaps and contradictions before writing code: wave size vs customer count, a 4 pm walk-in conflict, who buys the slots in the 2 to 6 pm montage, floor prices stored per merchant instead of per service, webhooks not reaching localhost | Build straight from the PRD, no trimmed spec. Simulator runs only in demo mode, so judges in live mode type as the customer and pay for real in test mode. Quick-reply chips sit alongside a working text input. Reset restores the clock and simulator too |
| 9 Oct | Claude Code + Supabase connector | Created the Supabase project, wrote the 11-table schema plus a demo_state table, and set read-only public access with Realtime | New, separate project so Reset can't touch anything else. Public GitHub repo as the code submission, deployed to Vercel from day one |
| 9 Oct | Claude Code | Wrote a deterministic seed generator: 60 customers across types (due, lapsed, regulars, VIPs, opted out, far away, recent), today's calendar designed to give 32 empty slots, 26.5 free chair-hours and 55.8% full, 90 days of history with walk-ins peaking at 4 pm, and about 52 synthetic merchants' hourly payments running 20% below normal today | Seed numbers must reproduce the PRD's demo day exactly. Hold the 5 pm block for walk-ins and release two 4 pm chairs for Riya and her sister |
| 9 Oct | Claude Code + in-app browser | Built the chair board as a standalone screen with Realtime updates, then checked every block state (booked, free, held, offered, released, paid) against live data | Chair board first, as the visual anchor for the video, before any other screen |
| 9 Oct | Claude Code + in-app browser | Took my mockups apart (a bundled HTML export of 10 screens), researched how Fresha, Square Appointments, Zenoti and Razorpay's own dashboard lay out a merchant's day, and rebuilt the UI: salon workspace with an account switcher, staff-column day calendar with service colours, dense tables instead of cards | Rejected the first build as "too AI-looking". Chose staff columns over chairs-as-rows because every salon tool works that way. Razorpay appears only where it would in real life (checkout, test mode, Agent Studio). WhatsApp replies must be live, not a static chat on the side |
| 9 Oct | Claude Code | Built the live loop: planner (walk-in forecast from same-weekday history scaled by area footfall; hold and release per hour), customer ranking, wave 1 as an approved WhatsApp template, the salon agent on Qwen returning JSON actions, and the pay page opening real Razorpay Checkout (HDFC-only block for the bank-funded price) | Live in-app phone rather than the real WhatsApp API, to cut setup risk with 4 days left. Prices, floors and times are enforced in code; the model only proposes |
| 9 Oct | Claude Code + Supabase | Wrote settle_offer() so the first confirmed payment wins inside one transaction: it carves the paid time out of the free block, cancels overlapping offers, books the customer, and a second payment is refunded | Floor checked on what the salon receives (₹330 + ₹50 HDFC clears a ₹350 floor) |
| 9 Oct | Claude Code | Simulator for demo mode only (wave 1 buyers, 1:30 pm footfall release of the held 5 pm hour, wave 2, walk-ins into held time, a call-me). Tuned so the demo day lands on the PRD's base case: 7 slots, ₹3,160, ₹150 HDFC-funded | Simulated customers only in demo mode; in live mode judges type as the customer and pay for real in test mode |
| 9 Oct | Claude Code | Daily report, settings, front desk, agent-to-agent negotiation (two Qwen agents with private limits, a real Razorpay order on a deal), landing page | Benchmark shows what similar salons fill on their own (18%) vs with the agent (30%), not a made-up gap |
| 9 Oct | Claude Code | Caught its own mistake: replies it had reported as "live" were the scripted fallback, because the model name in .env.local had been reverted and every model call returned 404. Fixed the model, re-ran every agent, and now tags each reply "model" or "script" | Keep the scripted switch as a recording safety net, but the default path must be the live model |
